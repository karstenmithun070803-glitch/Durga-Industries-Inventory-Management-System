# Prefix Codes & Smart Search

## Why prefix codes?

In an ERP system you frequently switch between screens. Seeing "001" alone is ambiguous — is it Customer 1 or Supplier 1? Prefixes make codes unambiguous at a glance.

## Prefix map

| Master | Prefix | Padding | Example |
|--------|--------|---------|---------|
| Customer | C | 3 digits | C001 |
| Supplier | S | 3 digits | S001 |
| Material | M | 3 digits | M001 |
| Unit | U | 2 digits | U01 |
| Tax Rate | T | 2 digits | T01 |
| Contractor | CON | 2 digits | CON01 |
| Vehicle / Job | J | 5 digits | J00001 |

## Code generation

Codes are auto-generated by the database (`SERIAL` columns). You never type a code — the system assigns the next number automatically when you add a record.

## Smart search

All table search boxes support three equivalent ways to find the same record:

| Input | Finds |
|-------|-------|
| `5` | Record with sequence number 5 |
| `M5` | Material number 5 |
| `M005` | Material number 5 (full code) |
| `M005 Angle` | Material 5 whose name contains "Angle" |

Implemented in `src/lib/utils.ts` → `matchesCode(search, prefix, num, pad)`.

## Combobox dropdowns

Combobox dropdowns (e.g., selecting a material in a form) use cmdk fuzzy search. The full formatted label (e.g., `M005 — Angle Iron`) is the search text — cmdk handles partial matches naturally. No extra logic needed.
